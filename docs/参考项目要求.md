# 参考项目要求（C++17 开源 API/代码设计）

> 目的：dts-framework 五层重构的 API/代码设计参考源。
> 来源：dds-deconstruction 会话 2026-07-31 输出（曾在另一环境丢失，2026-08-04 恢复并落盘）。
> 用法：每层重构时，按"看什么"定位到对应项目，先读源码再定义 API。

## 选择标准

| 标准 | 要求 |
|---|---|
| 语言标准 | **C++17 起步**（与我们一致，避免引用 C++20+ 专属写法） |
| 可读性 | 可人为 review、无 AI 坏味道、单文件职责单一 |
| 参考价值 | 分层清晰 / API 直观 / 类型安全，至少占一项 |

## 参考项目清单（按"看什么"分类）

### API 设计典范（看 API 怎么设计得直观、类型安全）

| 项目 | 参考点 | 本地路径 |
|---|---|---|
| **{fmt}(fmtlib)** | 现代 C++ API 标杆。模板+constexpr 让格式化 API 直观且编译期类型安全。看它怎么用 `format`/`print` 把复杂机制藏进干净接口 | `opensource/fmt` |
| **nlohmann/json** | "API 像自然语言"的典范（`j["key"]`、`get<T>()`）。看类型安全转换 + 单头文件的组织 | `opensource/json` |

### 分层架构（看分层 API 怎么切）

| 项目 | 参考点 | 本地路径 |
|---|---|---|
| **Asio(standalone)** | C++ 异步框架教科书。分层清晰：`io_context`/`executor`/`operation`，同步/异步 API 并存。看"层间职责怎么切" | `opensource/asio`（`asio/asio/include`） |
| **Boost.Beast** | 基于 Asio，看**协议层如何建在传输层上**（HTTP over TCP）——和 detmw（通信层）→ 域（业务层）分层对照 | `opensource/beast` |

### 线程/调度（和 detsched 直接相关）

| 项目 | 参考点 | 本地路径 |
|---|---|---|
| **oneTBB(TBB)** | 线程调度/并行框架。看任务调度、flow_graph 的 API，对比 detsched 的确定性调度接口设计 | `opensource/oneTBB` |
| **BS::thread_pool** | 小而美的线程池，现代 C++ 简洁 API 的范例（代码短、可读性极佳） | `opensource/thread-pool` |

### 同领域（DDS）

| 项目 | 参考点 | 本地路径 |
|---|---|---|
| **CycloneDDS(Eclipse)** | 另一 DDS 实现。C 语言但架构/代码质量高，可对比 Fast-DDS 的协议层，看"实现怎么做到可读" | `opensource/cyclonedds` |
| **Fast-DDS** | **反面参考**，重构时避免它的坏味道（可读性差） | `opensource/Fast-DDS` |

### 测试（质量兜底）

| 项目 | 参考点 | 本地路径 |
|---|---|---|
| **Catch2** | 测试框架，BDD 风格 API。看宏+模板怎么做出清爽接口 | `opensource/Catch2` |

## 重构时最有用 TOP 3

| 项目 | 对应诉求 |
|---|---|
| **{fmt}** | API 直观（→ 分层 API 重写） |
| **Asio** | 分层切法（→ 层间职责边界） |
| **BS::thread_pool** | 短小可读（→ 可读性达标） |

正好对应"分层 API + 可读性 + 可审计"三个诉求。

## 备注

- **Fast-DDS / CycloneDDS / spdlog / foonathan-memory** 本地已有（`opensource/`），作为同领域对照。
- 本清单为 API/代码设计的**参考源**，不构成三方库选型决定（选型后续单独做，见重构备忘录盲点 2.1）。
- 未标注版本的 clone 为 shallow `--depth 1` 拉取（当时最新），按日期记录即可。
