- 删 ReportBuf/FlushReports/AcquireReport 等（周期汇聚链路搁置）；OnTick 只留 ++m_tick + EvictExpired（TTL）
- dts_def.h 加 TaskRequest{taskId,status}；handler OnTaskActive 解 TaskRequest 标记 currentTask
- 修复静态库静态注册丢失：extractors.cpp 加 `void InitExtractors(){}` + run.cpp 显式调（强制 extractors.o 链接，否则 ExtractorRegistry 空）

## 追加：极限测试改造 + 内存安全（下午）

**data 收窄 + 极限测量**
- extractors.cpp 收窄到固定 10 cell dataId（CCellSlice 共用），量通道消息率
- webserver_mock 加 count/csv 双模式：count（只计数）量纯通道极限，csv 量 CSV 落地极限
- 实测（reliable depth=1000, data 切 10）：spa 14680 raw/s → data 收全 20000 → publish 43490（期望 200000，每帧 10 reliable write 拖慢，~2.17/帧）→ web 收 37060
- 瓶颈定位：**data 线程处理速率**（reliable DDS write 开销 + web 消费慢 → backpressure），count(4664fps) vs csv(4211fps) 接近说明瓶颈不在 CSV

**内存安全（防系统卡死/断连）**
- run_tune.sh 加内存守护：MEM_LIMIT_MB（默认 2G）后台 guard 监控 dts+web RSS，超限 kill 全部 + 报警 exit 2；trap cleanup 清残留
- clean_residue.sh：卡死后手动清（杀残留进程 + 清 /dev/shm 的 FastDDS SHM 段，kill -9 不释放 SHM 会累积撑爆）
- 验证：正常跑 guard 不触发；低阈值(10MB)触发（RSS 114MB > 10MB → kill 全部，0 残留）
- 注：dts 启动 RSS ~114MB（FastDDS participant 开销）
