## B. "环境劣化"根因破案：IP 分片重组不通（重写 08-17 以来的定性）

**现象史**：08-17 12:1x 起多端点跨进程发现"不可靠"（对端 reader 收 0）、32K UDP "不可达"，
历次定性为"网络栈限制/非代码回归"。

**今日实证链**（DDS 发现探针 /tmp/dds_probe.cpp，DomainParticipantListener）：
1. 多端点参与者（tune-dts 13 端点）：PDP 正常（参与者可见）、**SEDP 端点全 0**——整批丢失而非丢部分
2. 单端点参与者（plain-dts 1 端点）：端点正常发现
3. 排除项：发现模式（SIMPLE/STATIC 同败）、LOCAL_PEERS 纯 loopback 单播同败、UDP_ONLY 同败、
   SHM 残留段清理后同败 → 与组播/网卡无关
4. **根因**：FastDDS 把多条 SEDP 公告打包进单个 RTPS 报文（上限 65500B）→ 13 端点公告 >MTU 1500
   → **IP 分片** → 本机（WSL mirrored）**IP 分片重组投递不通** → 整报丢失 → 端点 0。
   1 端点公告不分片故正常；"32K UDP 不可达"同源（用户数据超 MTU 即 IP 分片即丢）。
   端点数与成败完全相关（plain 1 过 / domain77 ~10 败 / tune 13 败 / cross 15 败）。

**修复（detmw_fastdds.cpp，环境自适应开关）**：
- `DETMW_UDP_MTU=1400`：UDP 单传输 + RTPS 报文钉在 MTU 内 → 超出走 **RTPS 层分片（DATA_FRAG，
  可靠重传）**，不依赖 IP 分片。坑：FastDDS 要求描述符 maxMessageSize ≤ max_msg_size_no_frag
  （内置默认传输 65500 不满足且触发其空指针段错误）→ 必须显式建 UDP 描述符同步设值
- `DETMW_LOCAL_PEERS=1`（辅助开关）：元数据 127.0.0.1 单播 + 关组播（同机部署免组播依赖；
  实验证明 PDP 组播在本机可用，此开关备用于组播受限环境）
- 采用：run_web.sh / run_cross_test.sh / run_slevel.sh 默认 `DETMW_UDP_MTU:-1400`（可覆盖）；
  性能链 run_tune/run_steady 保持默认（SHM 大报文，量吞吐不量分片）

**验证**：
- 探针：tune-dts 13 端点全部 DISCOVERED（修复前 0）
- **全量 ctest 12/12 首次全绿**（本机历史最好 8/9→9/11）：bucket×2 + integration + cross_process
  （含 P1-3 远程命令往返断言）+ s_level_perf（32K×5 零丢，"不可达"解除）+ 5 单测 + plain_smoke
  + web_smoke，总时 87s
