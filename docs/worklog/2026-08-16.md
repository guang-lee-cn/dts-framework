# 2026-08-16：三级消息路由重构 + 评审问题修复迭代

> 背景：项目评审（docs/ 之外的口头评审）发现的问题 + 消息处理可扩展性重构。
> 目标形态：每个线程的 {data|task|log}_msg_handler.cpp 呈现为
> `{msgId, func(void* data, uint32_t datalen)}, // n 个消息流` 表驱动风格。

## A. 三级消息路由（核心重构）

**路由分层**：
- 第一层 sessionType（string）→ 第二层 sessionInst（string）：订阅期完成
  （gen_detmw.py 生成路由头 + bootstrap RegisterSubRoutes 决定端点进哪个线程 mailbox）
- 第三层 msgId（uint32）：**消息表分发**，落地在 msg_handler.cpp

**新增 infrastructure/include/msg_table.h**：
- `MsgHandlerFn = void (*)(void* data, uint32_t datalen)`（统一处理函数签名，data 可原地改）
- `MsgHandler{msgId, fn, name}` + `MsgTable`（静态表线性查表：Dispatch/Find/Count/At）
- `SessionMsgTable{sessionType, sessionInst, entries, count}`（第一/二层登记，bootstrap 用）

**三个 msg_handler.cpp 重构（if/else → 表）**：
- task：`{MSG_ID_TASK_ACTIVE, OnTaskActive}, {MSG_ID_TASK_CONFIG, OnTaskConfig}`
- data：`{MSG_ID_DATA_TASK_ACTIVE, OnTaskActive}, {MSG_ID_AGENT_DATA, OnAgentData},
  {MSG_ID_TIMER, OnTick}`
- log：`{MSG_ID_LOG_COLLECT, OnCollect}`
- 各暴露 `const SessionMsgTable* XxxSessionTable()`；新增业务流程 = 表加一行
- 链路签名：EntryFn / XxxEntry / XxxMsgHandlerDispatch 的 msg 改 `void*`（mailbox 已移
  所有权，允许原地处理；与 MsgHandlerFn 同签名）

**console `get_handlers [task|data|log]`**：bootstrap 登记，展示 sessionType.sessionInst
→ msgId → 处理函数名（新消息流自动可见，命令零改动）

## B. publish_internal mailbox 直通落地（D7/D8 兑现，detmw.cpp）

- `Communicator::Impl` 增 `localSubs`（endpoint → 订阅回调表，mutex 保护）；
  `subscribe()` 成功即登记
- `publish_internal`：命中本进程订阅者 → 直接调订阅回调（OnRouteMsg → mailbox.Send），
  免 DDS 序列化/传输/反序列化（一次拷贝 + 移所有权）；未命中回退 transport
- **语义变化**：task→data 的 msg2 外部不再可观测（契约 detmw.md §3 已更新）；
  外部 task 往返改走 msg7/msg8（nfoam_test/bench 同步）

- **msgId 查重 static_assert**：`MsgIdsUnique()`（msg_table.h，C++17 constexpr）编译期
  拦截表内重复 msgId（此前查表取第一个匹配会静默遮蔽），三个 handler 表 + 单测双保险
- **扩展配方写入契约**：contracts/contexts.md §3.1「新增一个消息流（三步）」——
  ① config 加端点（订阅/发布各一条，构建期自动派生路由/预建 writer）② 消息表加一行
  ③ 写处理函数；框架侧零改动（订阅自动、publish_internal 直通表自动、get_handlers 自动可见）
- 结论：处理器层扩展 = 一行 `{msgId, fun}`；完整链路多一步配置端点（框架既定设计：
  端点配置驱动，运行时零查表 + 静态发现 + 首包不丢）

## 追加：业务组路由语义落地（sessionInst = 业务组）

**语义确认**（需求）：同一线程 sessionType 固定；sessionInst 区分一类业务组（线程可挂
多组）；msgId 区分组内具体业务。

**实现**：
- **mailbox 携带 sessionInst**：MailMsg 增 `const char* sessionInst`（借指针指向订阅端点
  串，零拷贝；nullptr = 线程本地消息如 TIMER）；OnRouteMsg 盖章，publish_internal 直通
  同路径；EntryFn/入口/分发签名增 sessionInst 参数
- **业务组数组**：`{data|task|log}_msg_handler.cpp` 声明
  `constexpr SessionMsgTable kXxxGroups[]`（每组 = sessionType + sessionInst + 组内
  {msgId, fn} 表）；分发 = `FindSessionTable(sessionInst)` 选组 → 组内 MsgTable 查表
- **编译期护栏**：`MsgIdsUnique`（组内 msgId 唯一）+ 新增 `SessionGroupsValid`（组数组
  合法：sessionType 全部相同且非空 = 线程内固定、sessionInst 唯一 = 组不歧义）
- **MSG_ID_TIMER 归位**：线程本地机制，不属业务组，分发入口直接处理（data → OnTick）
- get_handlers 按组展示（实测：DTS.task / DTS.data / DTS.log，可按组过滤）
- 契约/架构文档同步（contracts/contexts.md §3.1 含"新业务组"配方）

**验证**：编译零警告；ctest 5/5（unit×3 含组语义用例 + integration + cross_process）；
get_handlers 实测输出组结构。
