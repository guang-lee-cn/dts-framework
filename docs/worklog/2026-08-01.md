## Bug 定位记录（重要）

### spa_mock use-after-free —— spdlog 时序暴露的潜伏 bug
- 现象：引入 spdlog 后集成测试 SEGFAULT，定位在 agent 读线程 `PingPongBuffer::ReadAndFlip`
- 归属：**spa_mock（测试辅助）**，非 dts、非 spdlog
- 根因：SpaMock 的 `m_pingpong` 栈成员，agent/writer 线程无停止机制，析构后仍访问 → use-after-free（从 mock 引入起就潜伏）
- spdlog 异步线程池改变退出时序，使访问时机撞上析构 → 暴露
- 修复：析构时 `m_stop → join writer → dts_agent_destroy`
- 教训：引入异步组件时，既有线程生命周期缺陷可能被时序暴露；先归属再下结论

### 其他
- **detmw.c 被 CMake 忽略**：顶层 `project(... CXX)` 只启 CXX，C 源（detmw.c/cJSON.c）静默跳过 → 补 `LANGUAGES C CXX`
- **TypeSupport 双重释放**：`TypeSupport` 是 `shared_ptr<TopicDataType>`，手动 `delete type` 为第二释放者（曾误判为 Fast-DDS bug）

## 关键决策

| 决策 | 理由 |
|---|---|
| detsched/detmw 命名空间 | 规避 `thread` 与系统冲突；det 前缀辨识度 |
| detmw 用 C ABI | 跨语言/编译器 ABI 稳定，上层不受内部实现影响 |
| 分段规约配置驱动生成 | 架构/调度组可维护，校验在生成器，业务零改动 |
| 实时线程异步日志 overrun_oldest | 日志不阻塞 data 等实时线程，满时丢最旧 |
| detmw 可靠 QoS | 对齐 S 级可靠需求，发现后不丢 |
| 只释放自己管理的资源 | detmw 不手动释放 DDS 对象，交 Fast-DDS；避免双释放 |
