# 2026-08-03：SHM bug 定界 + 决策走自研桶

## 事件

用户对"shm bug 是社区确认还是自研误判"提出两问，并要求在"修 WatchTask（方案 A）/ 自研桶（方案 B）"间做决策。

## 调查结论

1. **Bug 8 社区确认**：[eProsima/Fast-DDS #6114](https://github.com/eProsima/Fast-DDS/issues/6114)（`useBuiltinTransports=false` + SHM → 退出 SEGV，归因 `remove_port`，OPEN）；master 上 SharedMemGlobal.hpp 自 3.6.0 仅 uncrustify，未修；最新 v3.6.2 仍在影响范围。
2. **Bug 7 社区确认**：[#1666](https://github.com/eProsima/Fast-DDS/issues/1666)（段满竞态）+ [#6206](https://github.com/eProsima/Fast-DDS/issues/6206)（segment_size 不足告警）。
3. **gdb 复诊推翻早期归因**：崩在 `watched_ports_` 向量元素被写坏（`_M_ptr` 垃圾值），`remove_port` 的 `this` 有效 → **堆损坏，非 static 析构顺序**。方案 A（WatchTask 调用点换成员 ref）**经证无效**，作废。
4. **崩溃触发定界**：`useBuiltinTransports=false`（SHM-only）+ **任何** SHM 描述符（含默认 512KB）都崩；`useBuiltinTransports=true` 不崩。
5. **Bug 7 真因 = 段容量**：64MB 段下 32K×200 → 200/200 零丢、1MB×1 → 1/1 收到（默认 512KB 下 112/200）。

## 决策

**主线：自研桶（TransportInterface 扩展），不碰 FastDDS 源码。** 桶段 ≥64MB。方案 A 作废。

## 阶段①（BucketSegment）已落地并验证

`thirdparty/bucket/`（BucketSegment 共享内存环：shm_open+mmap、变长消息、多写单读、robust 写锁、futex 唤醒、先写后发布保崩溃安全）。跨进程冒烟全过：200×32K 紧突发 200/200、1MB×4 4/4、双 writer 200/200、1MB 桶装 6.4MB 背压不丢、writer 崩溃后接管 300/300。已接进工程 cmake（libbucket + bucket_smoke）。
