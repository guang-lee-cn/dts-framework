## 二、重构定位与目标

- **触发**:AI 自动生成代码大部分不符合预期 → 不可控、难人为审计、可读性差
- **用户**:自己(后续希望落地企业)
- **定位**:分层清晰、可人为审计的 DDS 确定性调度框架
- **核心原则**:**框架保持不动,重构代码实现(尤其分层 API)**
  - 不动:分层结构、层间依赖方向、运行时架构(线程/通信/部署)
  - 重写:各层 API 定义(签名/职责)+ 内部实现,逐目录逐文件
- **目标(SMART)**:
  1. 五层 API 重写完成(detmw / detsched / infrastructure / task·data·log / bootstrap)
  2. 可读性达标(可人为 review、无 AI 坏味道、单文件职责单一)
  3. 行为不回归(cpf/dpf 重构前后压测数据一致)

## 三、分层与建议

当前五层:通信 detmw / 调度 detsched / 基础设施 infrastructure / 业务域 task·data·log / 组合根 bootstrap。

**重构关键强化点(不推倒分层,重写时落实)**:
- 业务域 **domain(纯业务)零技术依赖**——不 include detmw/detsched,通过**端口(port)**访问通信/调度
- detmw / detsched 是**适配器**,实现端口
- 端口 = 夹层转换 API(自用直接实现,企业集成换适配器)
